# 发布后复盘规则

## 目标

帮助 Agent 基于用户提供的已发布小红书笔记内容和可见数据，完成流量诊断、人群关键词匹配、封面标题点击诊断、当前补救动作和下一篇实验建议，并在需要时生成本地 HTML 可视化复盘看板。复盘只做“可能原因”和“验证假设”，不承诺爆款，不把平台算法写成确定结论。

## 触发输入

支持且只支持以下数据入口：

- 手动数据：用户粘贴标题、正文、标签、发布时间、曝光、小眼睛/观看/阅读/查看数、点赞、收藏、评论、分享、关注、转化等。
- 截图识别：用户上传笔记页面、创作中心或数据截图；先提醒打码昵称、头像、私信、订单、联系方式和后台敏感信息。
- 单篇链接：抓取公开可见的笔记标题、正文、标签、封面/图片、发布时间和可见互动数。
- 主页链接：抓取公开可见的主页信息和当前可加载的公开笔记，用于账号内容结构与近期表现复盘。

链接抓取边界：

- 只使用公开可见信息。
- 不登录、不绕过验证码、不破解接口、不采集私信、订单或后台数据。
- 遇到验证码、权限限制、加载失败、字段不可见或平台限制时停止抓取，并友好提示用户提供截图或文字信息。

## 必要数据追问

- 小眼睛/观看数必问：`metrics.views` 对应小红书公开或后台里的小眼睛、观看、阅读、查看数；它代表已点进或已查看内容的量级，不等同于曝光。
- `metrics.exposure` 只表示曝光/展现；有曝光和观看时，才可判断点击效率或入口转化。
- 单篇链接抓不到 `views` 时，先问用户：`我没有拿到小眼睛/观看数，这会影响流量判断。请补充观看数，或回复“跳过”继续做不完整复盘。`
- 用户补充 views 后再输出完整报告；用户明确回复“跳过”后，报告必须标注“不完整流量诊断：缺少小眼睛/观看数，无法完整判断点击与流量质量”。
- 不把公开点赞、收藏、评论、分享反推成观看数或曝光。

## 流量漏斗诊断

按链路逐项判断：

- 曝光：选题、账号基础、发布时间、标签和平台分发可能影响初始触达；缺曝光时不计算点击率。
- 观看/小眼睛：封面、标题、首图信息密度、搜索关键词和人群匹配可能影响点击；缺 views 时先追问或标注不完整流量诊断。
- 点赞：情绪共鸣、观点表达、审美和即时认同可能影响点赞。
- 收藏：清单、步骤、参数、避坑、模板和复用价值可能影响收藏。
- 评论：问题设计、争议边界、经验征集和置顶评论可能影响讨论。
- 分享：信息密度、社交货币、实用清单和情绪表达可能影响转发。
- 关注/转化：账号人设、系列感、信任证据、行动路径和商品/服务承接可能影响后续动作。

数据缺失时：

- 不计算不可见的点击率、转化率或后台指标。
- 可用“无法判断，需要补充曝光/小眼睛/观看/关注等数据”说明缺口。
- 不把单篇链接公开互动数当作完整后台表现。

重点输出：

- 流量来自哪里，卡在哪一段：曝光不足、点击不足、内容承接不足、互动设计不足或转化承接不足。
- 已知 `views` 时，计算点赞率、收藏率、评论率、分享率和总互动率；有 `exposure` 时，再计算观看/曝光转化。
- 没有 `exposure` 时，封面标题点击诊断只能弱判断，必须写明“缺曝光，不能确认点击率”。

## 封面标题点击诊断

- 结合封面/首图、标题、首图文字、目标人群和 `views`/`exposure` 判断入口吸引力。
- 判断标题是否把核心利益点说清楚，是否包含赛道词、人群词、问题词或长尾搜索词。
- 判断封面是否能在 1 秒内让目标人群看懂“这篇和我有关吗”。
- 输出“保留点、问题点、当前可补救动作、下一篇实验”。

## 目标人群与关键词匹配

复盘时联网搜索同类笔记/赛道，查询方向包括：

```text
笔记标题 小红书 同类笔记 目标人群
核心标签 小红书 搜索关键词 热门标签
赛道词 小红书 标题 表达 关键词布局
目标人群词 小红书 痛点 搜索词
```

采用结果只用于判断：

- 这篇笔记更像推荐流量内容还是搜索流量内容。
- 目标人群是否明确，封面标题是否能让这群人自我识别。
- 当前标签和正文关键词是否覆盖赛道词、人群词、痛点词、内容形态词和长尾搜索词。
- 下一篇应补哪些关键词、标签或标题表达。

联网不可用或结果不可靠时，说明“未完成联网关键词校验”，并用现有标题、标签和正文做弱判断。

## 附录参考评分

六维评分保留但弱化，不放在主结论，不生成主导性的总分。

固定维度：

1. 入口吸引力：封面/首图、标题钩子、场景识别度和点击动机。
2. 标题搜索力：关键词、赛道词、场景词、长尾搜索价值和表达清晰度。
3. 正文承接力：开头钩子、中段信息、真实感、节奏和读完动力。
4. 收藏价值：清单化、步骤化、参数化、避坑点和复用价值。
5. 评论互动：置顶评论、引导问题、讨论空间和回复延展性。
6. 转化/关注潜力：账号人设、系列感、信任证据、行动路径和关注理由。

每项输出：

- `score`：0-100；数据不足时可为空或标注为“数据不足”。
- `evidence`：来自标题、正文、图片、标签或数据的具体依据。
- `confidence`：高/中/低；公开链接数据或截图缺字段时通常为中或低。

如果展示总分，只能放在附录，并说明“仅供参考，主结论以流量漏斗和行动建议为准”。

## HTML 看板

用户要求“生成网页/HTML/看板/可视化报告”时：

1. 先完成复盘判断，再整理 JSON。
2. 调用 `python3 scripts/generate_review_report.py --input <review.json> --output-dir outputs/reports`。
3. 返回生成的本地 HTML 路径。
4. 如果 `scripts/` 目录、`generate_review_report.py`、`python3`、输入 JSON 或输出目录不可用，按 [脚本降级输出规则](fallback_outputs.md) 输出 `## 发布后复盘报告（Markdown 降级版）`。

HTML 看板必须包含：

- 用户输入的图片、标题、正文、标签、链接和发布时间。
- 数据结论、流量漏斗、封面标题点击诊断、目标人群与关键词匹配。
- 指标柱状图、互动占比饼图和“内容 → 观看/互动 → 流量卡点 → 行动建议”的连线图。
- 当前这篇补救动作、下一篇迭代实验、风险边界。
- 附录参考评分；六维雷达图只能放在附录，不作为首屏核心。
- 下一篇实验卡：假设、改法、成功指标和执行建议。

下一篇建议必须落到可执行项，至少覆盖封面、标题、开头、正文结构、标签、评论钩子、发布时间或选题方向中的 3 项。

## 输出文本模板

生成 HTML 后，在对话中简短说明：

```markdown
已生成发布后复盘 HTML 看板：
- 文件：[outputs/reports/xxx.html]
- 包含：数据结论、流量漏斗、封面标题点击诊断、目标人群与关键词匹配、柱状图、饼图、连线图和下一篇实验卡
- 提醒：本次复盘只基于已提供/公开可见数据，缺失字段未做推断
```

如果无法生成 HTML，说明缺少的字段或失败原因，并输出 Markdown 降级版报告；需要更多数据时再引导用户补充截图或文字信息。
