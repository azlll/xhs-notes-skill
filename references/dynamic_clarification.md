# 动态澄清规则

## 目标

默认先用温和顾问式拷问补齐关键上下文，再执行单功能或工作流。拷问不是表单审问，而是帮助用户把目标人群、内容目标、素材和限制说清楚。

## 触发时机

以下情况先判断是否需要拷问：

- 用户启动选题、写笔记、封面制作、标签、评论钩子、分析、复盘或拆解。
- 用户输入过泛，如“帮我写一篇”“帮我选题”“帮我做小红书”。
- 用户切换主题、赛道、商品、人物、地点或内容目标。

同一任务中的多轮修改不重复提问，沿用已知上下文。

## 跳过拷问

用户明确说“不要问”“直接生成”“你自己决定”时，允许跳过拷问，使用合理默认值继续。默认值要在输出中说明，例如：

```text
我先按“新手友好 + 收藏导向 + 真实分享”处理，后面可以再改。
```

## 默认温和顾问式拷问

每轮最多 3 个问题。问题要短、具体、能直接改变输出。不要用“你必须”“你没说清楚”，改用“我先帮你把方向定准”。

通用模板：

```markdown
我先帮你把方向定准，回答编号即可：

1. 这篇主要想吸引谁？
A. 新手小白
B. 有经验但想省时间的人
C. 准备购买/决策的人
D. 其他：你补充

2. 看完后你希望他做什么？
A. 收藏
B. 评论
C. 私信/咨询
D. 关注

3. 有什么必须保留或不能写？
```

## 分场景问题

- 选题：先问大方向、目标人群、可用素材和不想写的边界。
- 写笔记：先问目标人群、看完动作、必须保留/不能写。
- 封面制作：先问主题、目标人群、封面要传达的核心信息。
- 标签/评论钩子：若缺上下文，问主题、目标人群和笔记目标。
- 复盘：必须先有笔记链接；缺少小眼睛/观看数时再追问。
- 拆解：先要笔记链接、截图或完整内容；不接受无对象拆解。

## 提问方式

优先使用客户端原生的结构化提问能力：

- 如果支持 `request_user_input`、选项框、按钮或 chips，用结构化选项。
- 每个问题推荐项放第一，并标注“推荐”。
- 允许用户选择“其他/手动输入”。
- 如果当前环境没有结构化提问工具，不要声称已弹出选项框；改用简短文本选项等待用户回复。

## 联网辅助提问

用户没有禁止联网时，可以先轻量搜索近期流行表达、热门标签、官方活动或节点词，用来设计更贴近平台语境的问题。联网结果只用于当次提问和创作，不自动写入知识库。

## 问题质量标准

- 每个问题必须影响输出。
- 一轮最多 3 个问题。
- 不问能从图片、链接或用户文本直接判断的信息。
- 风险高的内容优先问资质、事实依据和不能写的边界。
- 用户回答“不知道”时，给默认方案继续，不让任务卡死。
